Система логирования

В приложении используется простая, но эффективная система логирования на основе статического класса Logger из пространства имён LLMCodeExporter.Infrastructure.Utils. Эта система применяется во всех консольных компонентах: основном CLI, импортёре (LLMCode_Importer) и всех внутренних сервисах. Для веб-конфигуратора используется отдельный механизм (тост-уведомления и console.log), но общая философия логирования сохраняется. Логи помогают отслеживать работу программы, диагностировать ошибки и анализировать производительность.

1. Где хранятся логи

Все логи сохраняются в папке: 

Документы/LLMCodeExporter/Logs/

Каждый запуск программы создаёт отдельный файл с именем:
log_ГГГГ-ММ-ДД_ЧЧММСС.txt
Пример: log_2026-06-19_214538.txt

Автоматическая очистка: при запуске программа удаляет логи старше 30 дней (вызывается Logger.CleanOldLogs(30)). Это предотвращает переполнение диска.

Логи импортёра: Утилита LLMCode_Importer также использует этот же логгер – все её сообщения записываются в тот же файл сессии, что позволяет отслеживать полный цикл работы (экспорт → импорт) в одном месте.

1.1 Структура лог-файла

Каждый файл начинается с заголовка сессии, затем каждая запись имеет вид: 

[ВРЕМЯ] [УРОВЕНЬ] Сообщение

Пример реального лог-файла (с интеграцией импортёра):

[21:45:38] [INFO] === Приложение запущено === [21:45:38] [INFO] Режим: Interactive [21:45:38] [INFO] Система: Unix 6.8.0 [21:45:38] [INFO] Текущая директория: /home/user/project [21:45:38] [INFO] Запрос ввода: Введите путь к проекту [21:45:42] [INFO] [Попытка 1] Получен путь: /home/user/MyProject [21:45:42] [INFO] Путь к проекту: /home/user/MyProject [21:45:42] [SUCCESS] Сканирование завершено: 42 файлов, ~12,345 токенов [21:45:45] [WARN] Проект большой. Рекомендуется: Balanced режим или фильтрация [21:45:50] [INFO] Начало экспорта проекта 'MyProject' в режиме Balanced [21:45:51] [INFO] Обработан [1/42]: src/Program.cs [21:45:51] [ERROR] Ошибка при чтении src/UnicodeFile.cs: System.IO.IOException: Нет доступа [21:45:55] [SUCCESS] Экспорт завершен! Обработано файлов: 42 [21:46:02] [INFO] === Импортёр запущен (--start-input) === [21:46:02] [INFO] Начало распаковки снапшота: snapshot.md [21:46:03] [SUCCESS] Распаковано файлов: 42 [21:46:03] [INFO] === Импортёр завершён === [21:46:05] [INFO] === Приложение завершено ===

2. Уровни логирования

В системе используются четыре уровня, каждый со своим назначением:

  • INFO – стандартные информационные сообщения: запуск, завершение, шаги процесса, ввод пользователя, прогресс.
  • WARN – предупреждения: некритичные проблемы, которые не останавливают выполнение (например, проект большого размера, исключённые файлы, некорректный выбор пользователя).
  • ERROR – ошибки: проблемы с чтением файлов, исключения, сбои в работе сервисов. Они не останавливают выполнение, но записываются для диагностики.
  • SUCCESS – успешное завершение важных этапов: сканирование, экспорт, загрузка навигации, распаковка снапшота.

2.1 Какие события логируются

  • Запуск и завершение – начало и конец сессии.
  • Аргументы командной строки – если запуск в CLI-режиме, логируется режим.
  • Ввод пользователя – каждая попытка ввода пути, выбора в меню.
  • Сканирование проекта – начало, количество найденных и исключённых файлов, применённые фильтры.
  • Экспорт – начало, прогресс по файлам, размеры, степень сжатия.
  • Импорт (распаковка снапшота) – начало, количество распакованных файлов, ошибки доступа или невалидных блоков.
  • Ошибки – любые исключения с полным стеком вызовов (если доступен).
  • Предупреждения – например, если проект превышает рекомендуемый размер.
  • Успешные операции – завершение сканирования, экспорта, импорта, загрузки компонентов (навигация, футер).

3. Внутреннее устройство Logger

Класс Logger — статический, все методы доступны без создания экземпляра.

3.1 Основные методы

  • static void Log(string message, LogLevel level = LogLevel.Info)
    • Что делает: записывает сообщение в лог-файл с указанным уровнем.
    • Ожидает: строку сообщения и опционально уровень.
    • Алгоритм:
      1. Проверяет инициализацию (вызывает Initialize()).
      2. Формирует строку: [HH:mm:ss] [УРОВЕНЬ] Сообщение.
      3. Добавляет строку в конец текущего лог-файла через File.AppendAllText.
  • static void LogError(string message, Exception ex = null)
    • Что делает: записывает сообщение об ошибке. Если передан Exception, добавляет стек вызовов.
    • Ожидает: сообщение и опционально исключение.
    • Вызывает: Log(message + details, LogLevel.Error).
  • static void LogSuccess(string message)
    • Что делает: записывает успешное завершение этапа.
    • Вызывает: Log(message, LogLevel.Success).
  • static void LogWarning(string message)
    • Что делает: записывает предупреждение.
    • Вызывает: Log(message, LogLevel.Warning).

3.2 Вспомогательные методы

  • static string GetAppFolderPath()
    • Что делает: возвращает путь к папке приложения (Документы/LLMCodeExporter).
    • Связь: использует Environment.GetFolderPath(Environment.SpecialFolder.MyDocuments).
  • static string GetCurrentLogFile()
    • Что делает: возвращает полный путь к текущему лог-файлу сессии.
    • Используется: в InteractiveMenu.ShowExportResult для вывода пользователю.
  • static void CleanOldLogs(int daysToKeep = 30)
    • Что делает: удаляет все лог-файлы старше указанного количества дней.
    • Вызывается: автоматически при инициализации Logger.
    • Алгоритм: сканирует папку Logs, удаляет файлы с датой создания раньше DateTime.Now.AddDays(-daysToKeep).

3.3 Инициализация (метод Initialize)

Вызывается автоматически при первом обращении к любому методу Logger. Создаёт структуру папок, формирует имя нового лог-файла и записывает заголовок сессии.

  • Создаёт папку Документы/LLMCodeExporter/Logs/ (если её нет).
  • Генерирует имя файла: log_yyyy-MM-dd_HHmmss.txt.
  • Записывает шапку: 
                                    ================================================================================
                                LLM Code Exporter - Лог сессии
                                Запуск: 19.06.2026 21:45:38
                                ================================================================================

4. Использование логирования в коде

Logger интегрирован во все ключевые места:

  • Program.cs (CLI) – логирует запуск, режим, системную информацию, ошибки, а также передачу управления импортёру.
  • LLMCode_Importer.Program – логирует начало распаковки, количество найденных блоков, ошибки доступа к файлам.
  • FileScanner.ScanProject – логирует начало сканирования, количество файлов до/после фильтрации, успех.
  • ExportService.ExportProject – логирует начало, прогресс по каждому файлу, завершение со статистикой.
  • InputHelper – логирует каждый ввод пользователя (содержимое, номер попытки, ошибки).
  • InteractiveMenu – логирует выбор пользователя, применение presets, отмену.
  • Все утилиты (при необходимости) – могут добавлять диагностические сообщения для отладки.

4.1 Пример логирования в коде

// В FileScanner
Logger.Log($"Начало сканирования: {projectPath}");
// ...
Logger.Log($"Найдено файлов (до фильтрации): {allFiles.Length}");
// ...
Logger.LogSuccess($"Сканирование завершено: {projectInfo.TotalFiles} файлов, ~{projectInfo.EstimatedTokens:N0} токенов");

// В ExportService
Logger.Log($"Начало экспорта проекта '{projectInfo.ProjectName}' в режиме {settings.Mode}");
// ...
Logger.Log($"Обработан [{processedFiles}/{projectInfo.TotalFiles}]: {file.RelativePath}");
// ...
Logger.LogSuccess($"Экспорт завершен! Обработано файлов: {projectInfo.TotalFiles}");
Logger.Log($"Оригинальный размер: {originalSize:N0} символов (~{originalSize / 4:N0} токенов)");

// В InputHelper
Logger.Log($"Запрос ввода: {message}");
Logger.Log($"[Попытка {attemptCount}] Получен ввод: {(string.IsNullOrWhiteSpace(input) ? "<пустой>" : input)}");
// ...
Logger.LogError($"Ошибка при вводе (попытка {attemptCount})", ex);

// В SnapshotUnpacker.UnpackAsync
Logger.Log($"Начало распаковки снапшота: {snapshotPath}");
// ...
Logger.Log($"Распакован файл: {relativePath}");
// ...
Logger.LogSuccess($"Распаковано файлов: {result.ExtractedCount}");

5. Управление логами

  • Автоматическая очистка: при запуске удаляются файлы старше 30 дней.
  • Ручная очистка: вы можете удалить папку Документы/LLMCodeExporter/Logs/ вручную.
  • Просмотр: любой текстовый редактор (Notepad, VS Code) откроет лог-файл.
  • Размер: логи не занимают много места (обычно < 1 МБ на сессию). Если проект очень большой, количество записей может увеличиться, но всё равно остаётся небольшим.
