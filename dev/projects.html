Обзор проектов (сборок)

Решение состоит из пяти проектов, каждый из которых отвечает за свой слой или функциональность: CLI (точка входа), Core (модели и интерфейсы), Infrastructure (реализации), Importer (распаковка снапшотов) и Web-конфигуратор (графический интерфейс). Ниже приведено краткое описание каждого проекта, а затем перечислены все ключевые классы/интерфейсы с их методами.

1. LLMCodeExporter.CLI

Назначение: Точка входа в приложение. Обрабатывает аргументы командной строки, запускает интерактивный режим, инициализирует сервисы и управляет процессом экспорта.

Зависимости: Ссылается на LLMCodeExporter.Core, LLMCodeExporter.Infrastructure и LLMCode_Importer (для вызова через --start-input).

1.1 Program

  • static async Task<int> Main(string[] args) – точка входа, парсит аргументы, определяет режим.
  • static ParseResult ParseArguments(string[] args) – разбирает ключи и возвращает настройки.
  • static void ShowHelp() – выводит справку.
  • static string NormalizeProjectPath(string path) – очищает путь и преобразует .csproj в директорию.

1.2 InteractiveMenu (статический класс)

  • static ExportSettings ConfigureSettings(ProjectInfo projectInfo) – пошаговый опрос пользователя.
  • static void ShowProjectStats(ProjectInfo projectInfo) – вывод статистики.
  • static void ShowExportResult(ExportResult result) – вывод результата экспорта.
  • static void ConfigureCustomFilters(ExportSettings settings) – запрос дополнительных паттернов.

1.3 InputHelper (статический класс)

  • static string ReadLine(...) – безопасное чтение строки.
  • static string ReadDirectoryPath(...) – чтение пути с проверкой существования.
  • static bool ReadYesNo(...) – чтение Y/N.
  • static int ReadChoice(...) – чтение выбора из диапазона.

2. LLMCodeExporter.Core

Назначение: Содержит модели данных и интерфейсы. Ядро бизнес-логики, не зависит от внешних слоёв.

Зависимости: Не зависит ни от каких других проектов.

2.1 Модели (пространство имён LLMCodeExporter.Core.Models)

  • ProjectInfo – информация о проекте (путь, файлы, метаданные).
  • FileMetadata – данные о файле (путь, размер, оценка токенов).
  • ExportMetadata – статистика экспорта (режим, количество файлов, токены, фильтры).
  • ExportSettings – настройки пользователя (режим, фильтры, формат и т.д.) с методами-пресетами.
  • ExportResult – результат экспорта (успех, путь, ошибки).
  • ProjectType (enum) – типы проектов (CSharp, Python, WebApp, Hybrid и т.д.).
  • LanguageSettings – настройки для конкретного языка (расширения, папки исключений).

2.2 Интерфейсы (пространство имён LLMCodeExporter.Core.Interfaces)

  • IProjectAnalyzer – анализ проекта (определение типа, сканирование, архитектура).
  • IFileScanner – сканирование файлов с фильтрацией.
  • ICodeProcessor – обработка кода (удаление комментариев, пустых строк).
  • ICodeOptimizer – оптимизация кода (сворачивание методов, минификация).
  • IOutputFormatter – форматирование отчёта (заголовок, файл, футер).
  • IExportService – основной сервис экспорта.

3. LLMCodeExporter.Infrastructure

Назначение: Реализует интерфейсы Core, содержит логику работы с файловой системой, оптимизацию, форматирование и утилиты.

Зависимости: Ссылается на LLMCodeExporter.Core.

3.1 Реализации интерфейсов

  • FileScanner – сканирует директории, применяет фильтры.
  • UniversalProjectAnalyzer – определяет тип, анализирует архитектуру и зависимости.
  • PythonProjectAnalyzer – специализированный анализатор для Python.
  • CodeProcessor – удаляет комментарии и пустые строки.
  • CodeOptimizer – оптимизирует код в зависимости от режима (Compact/Balanced).
  • ExportService – основной сервис, управляет всем процессом экспорта.
  • MarkdownFormatter – генерирует отчёт в Markdown.
  • PlainTextFormatter – генерирует отчёт в Plain Text.
  • UniversalCodeOptimizer – упрощённая оптимизация для всех языков.

3.2 Утилиты (пространство имён LLMCodeExporter.Infrastructure.Utils)

  • Logger – запись логов в Documents/LLMCodeExporter/Logs.
  • PatternMatcher – сопоставление файлов с паттернами (wildcard).
  • ProjectStructureBuilder – построение дерева и статистики.
  • NavigationGenerator – генерация Quick Links.
  • ArchitectureAnalyzer – определение слоёв и архитектурного стиля.
  • DependencyAnalyzer – построение графа зависимостей (Mermaid).
  • AnchorGenerator – создание якорей для Markdown.
  • MethodGrouper – группировка методов по семантике.
  • ProjectTypeDetector – автоопределение типа проекта.

4. LLMCode_Importer (импортёр снапшотов)

Назначение: Утилита для распаковки файлов из Markdown-снапшота, созданного основным экспортёром. Восстанавливает структуру папок и файлов.

Зависимости: Не зависит от других проектов решения (самодостаточный). Использует только стандартные библиотеки .NET.

4.1 Program

  • static async Task<int> Main(string[] args) – точка входа, маршрутизирует в CLI или интерактивный режим.
  • static async Task<int> RunCliAsync(string[] args) – обрабатывает аргументы командной строки.
  • static async Task<int> RunInteractiveAsync() – пошаговый опрос пользователя.
  • static async Task<int> UnpackCoreAsync(string snapshotPath, string outputRoot, bool overwrite) – общая логика распаковки.

4.2 SnapshotUnpacker

  • async Task<UnpackResult> UnpackAsync(string snapshotPath) – читает снапшот, ищет блоки ## 📄 `путь`, создаёт файлы.

4.3 ConsoleHelper

Статический класс для работы с консолью: цветной вывод, запросы ввода, справка.

4.4 Модели

  • UnpackerOptions – настройки (выходная папка, перезапись, путь по умолчанию).
  • UnpackResult – результат распаковки (количество файлов, корневая папка).

5. files-web-wiki – веб-конфигуратор

Назначение: Графический интерфейс для настройки параметров экспорта. Работает в браузере, сохраняет конфигурации в localStorage.

Структура: HTML + CSS + vanilla JavaScript (модульная архитектура). Не требует сборки – открывается прямо в браузере.

5.1 Модули (папка modules/)

  • dom.js – работа с DOM-элементами, рендеринг истории, тосты, управление модалкой.
  • providers.js – загрузка/сохранение конфигураций в localStorage, история, применение пресетов.
  • generators.js – построение командной строки на основе полей формы.
  • clipboard.js – копирование команды и экспорт истории в JSON.
  • config.js – константы (справка, ключи хранилища).
  • utils.js – debounce, валидация конфигураций, безопасный парсинг JSON.
  • app.js – точка входа, инициализация, подписка на события.

5.2 Взаимодействие с основным приложением

Веб-конфигуратор генерирует команду для запуска LLMCodeExporter.CLI (или run.sh) с выбранными параметрами. Пользователь может скопировать команду и выполнить в терминале. Также поддерживается настройка импортёра (путь к run.sh в настройках).

Резюме

  • Core – определяет, что нужно делать (интерфейсы) и какие данные (модели).
  • Infrastructure – реализует как это делать (файловая система, оптимизация, форматирование).
  • CLI – связывает всё вместе и управляет пользовательским взаимодействием.
  • Importer – самодостаточная утилита для распаковки снапшотов.
  • Web-конфигуратор – графический интерфейс для настройки параметров без консоли.
