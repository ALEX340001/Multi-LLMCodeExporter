Архитектура импортёра (LLMCode_Importer)

LLMCode_Importer – это утилита командной строки для распаковки файлов из Markdown-снапшота, созданного основным экспортёром. Она восстанавливает исходную структуру проекта, сохраняя вложенность папок и содержимое файлов. Импортёр может работать как самостоятельное приложение, так и вызываться через основной CLI с флагом --start-input.

1. Общая структура проекта

Импортёр состоит из следующих ключевых классов (все находятся в пространстве имён LLMCode_Importer):

  • Program – точка входа, обрабатывает аргументы, запускает интерактивный или CLI-режим.
  • SnapshotUnpacker – основной класс, выполняющий распаковку: парсит Markdown, создаёт файлы и папки.
  • UnpackerOptions – record с настройками: выходная папка, перезапись, путь к снапшоту по умолчанию.
  • UnpackResult – record с результатом: количество распакованных файлов и список путей.
  • ConsoleHelper – статические методы для цветного вывода, интерактивных запросов и справки.

2. Поток выполнения

Импортёр может быть запущен в двух режимах:

2.1 Интерактивный режим (без аргументов)

1
Program.Main() вызывает RunInteractiveAsync().
2
ConsoleHelper.PrintHeader() – вывод заголовка.
3
ConsoleHelper.AskForSnapshotPath() – запрос пути к снапшоту с валидацией существования файла.
4
ConsoleHelper.AskForOutputRoot() – запрос выходной папки (по умолчанию текущая).
5
ConsoleHelper.AskForOverwrite() – запрос флага перезаписи (по умолчанию true).
6
Создаётся UnpackerOptions и экземпляр SnapshotUnpacker.
7
Вызов UnpackAsync(snapshotPath) – основной процесс распаковки.
8
Вывод результата через ConsoleHelper.PrintSuccess().

2.2 CLI-режим (с аргументами)

1
Program.Main() вызывает RunCliAsync(args).
2
Парсинг аргументов: --output, --config, --overwrite/--no-overwrite, --help.
3
Если указан --config, загружается unpacker.settings.json (параметры CLI имеют приоритет).
4
Создаются UnpackerOptions и SnapshotUnpacker.
5
Вызов UnpackAsync(snapshotPath).
6
Вывод результата в консоль.

2.3 Запуск через основной CLI (--start-input)

1
Пользователь вызывает LLMCodeExporter.CLI --start-input snapshot.md --output ./restored.
2
Основной CLI определяет первый аргумент --start-input и передаёт управление LLMCode_Importer.Program.Main() с остальными аргументами.
3
Импортёр выполняется в CLI-режиме (или интерактивном, если аргументов после --start-input нет).
4
После завершения импортёра управление возвращается основному CLI, который завершает работу.

3. Ключевые методы

3.1 SnapshotUnpacker.UnpackAsync(string snapshotPath)

Назначение: Основной метод распаковки.

Алгоритм:

  1. Проверяет существование файла снапшота; если нет – выбрасывает FileNotFoundException.
  2. Читает всё содержимое файла асинхронно (File.ReadAllTextAsync).
  3. Применяет регулярное выражение FileHeaderRegex для поиска блоков вида: 
    ## 📄 `относительный/путь/к/файлу`
```(язык)
содержимое
```
  4. Для каждого совпадения:
    • Извлекает относительный путь и код.
    • Нормализует путь (заменяет / на разделитель ОС).
    • Создаёт все необходимые директории (Directory.CreateDirectory).
    • Если файл уже существует и _options.Overwrite == false – пропускает с уведомлением.
    • Иначе записывает код в файл (File.WriteAllTextAsync).
  5. Возвращает UnpackResult с количеством распакованных файлов и списком путей.

3.2 Program.Main(string[] args)

Назначение: Точка входа.

  • Если args.Length == 1 и аргумент – --help, -h или /? – выводит справку и завершает работу.
  • Если args.Length == 0 – запускает интерактивный режим (RunInteractiveAsync).
  • Иначе – запускает CLI-режим (RunCliAsync).

3.3 ConsoleHelper – вспомогательные методы

  • PrintHeader() – выводит заголовок с логотипом.
  • PrintHelp() – выводит справку по использованию.
  • AskForSnapshotPath() – интерактивный запрос пути с проверкой существования файла.
  • AskForOutputRoot() – запрос выходной папки с созданием, если её нет.
  • AskForOverwrite() – запрос флага перезаписи (Y/n).

4. Интеграция с основным CLI (флаг --start-input)

В основном CLI (LLMCodeExporter.CLI) добавлена проверка первого аргумента. Если он равен --start-input, то управление передаётся импортёру: 

// В Program.cs основного CLI
if (args.Length > 0 && args[0] == "--start-input")
{
    var importerArgs = args.Skip(1).ToArray();
    return await LLMCode_Importer.Program.Main(importerArgs);
}

Это позволяет пользователям использовать единую точку входа для экспорта и импорта, не запоминая отдельные команды.

5. Логирование

Импортёр использует тот же статический класс Logger, что и основное приложение (из LLMCodeExporter.Infrastructure.Utils). Это обеспечивает единый формат логов и хранение в одной папке (Документы/LLMCodeExporter/Logs/).

Все сообщения импортёра записываются в тот же файл сессии, что и логи основного CLI (если запущен через --start-input), что упрощает отслеживание полного цикла работы.

Пример логирования в импортёре: 

Logger.Log($"Начало распаковки снапшота: {snapshotPath}");
// ...
Logger.Log($"Распакован файл: {relativePath}");
// ...
Logger.LogSuccess($"Распаковано файлов: {result.ExtractedCount}");

6. Примеры использования

Интерактивный режим

# Запуск без аргументов
LLMCode_Importer

# После запуска:
# 1. Укажите путь к снапшоту (например, snapshot.md)
# 2. Укажите выходную папку (Enter для текущей)
# 3. Выберите, перезаписывать ли файлы (Y/n)

CLI-режим

# Базовый запуск
LLMCode_Importer snapshot.md --output ./restored

# С запретом перезаписи
LLMCode_Importer snapshot.md --no-overwrite

# С указанием конфигурационного файла
LLMCode_Importer snapshot.md --config unpacker.settings.json

Через основной CLI

LLMCodeExporter.CLI --start-input snapshot.md --output ./restored
