Обзор проектов (сборок)

Решение состоит из трёх проектов, каждый из которых отвечает за свой слой в архитектуре: CLI (точка входа), Core (модели и интерфейсы) и Infrastructure (реализации и утилиты). Ниже приведено краткое описание каждого проекта, а затем перечислены все ключевые классы/интерфейсы с их методами и пояснениями.

1. LLMCodeExporter.CLI

Назначение: Точка входа в приложение. Обрабатывает аргументы командной строки, запускает интерактивный режим (пошаговый опрос), инициализирует сервисы и управляет всем процессом экспорта.

Зависимости: Ссылается на LLMCodeExporter.Core и LLMCodeExporter.Infrastructure.

1.1 Program

Назначение: Статический класс с методом Main – точка входа.

  • static void Main(string[] args)
    • Что делает: парсит аргументы, определяет режим (интерактивный или CLI), создаёт экземпляры сервисов, запускает экспорт.
    • Ожидает: массив строк (args) – аргументы командной строки.
    • Возвращает: ничего (завершает работу с кодом 0 при успехе, иначе 1).
  • static (ExportSettings settings, string projectPath, bool showHelp, bool hasCliArgs) ParseArguments(string[] args)
    • Что делает: разбирает ключи (--mode, --exclude и т.д.) и возвращает настройки.
    • Ожидает: массив аргументов.
    • Возвращает: кортеж с настройками, путём, флагом помощи и флагом CLI-режима.
  • static void ShowHelp()
    • Что делает: выводит справку по использованию в консоль.
  • static string NormalizeProjectPath(string path)
    • Что делает: очищает путь от кавычек, преобразует путь к файлу .csproj в путь к папке.
    • Ожидает: строку с путём.
    • Возвращает: нормализованный путь.

1.2 InteractiveMenu (статический класс)

Назначение: Реализует интерактивный пошаговый опрос пользователя.

  • static ExportSettings ConfigureSettings(ProjectInfo projectInfo)
    • Что делает: последовательно спрашивает тип проекта, режим, фильтры, формат и возвращает готовый объект ExportSettings.
    • Ожидает: ProjectInfo (для отображения статистики).
    • Возвращает: ExportSettings (или null, если пользователь отменил).
  • static void ShowProjectStats(ProjectInfo projectInfo)
    • Что делает: выводит в консоль статистику (количество файлов, токенов, предупреждения о размере).
    • Ожидает: ProjectInfo.
  • static void ShowExportResult(ExportResult result)
    • Что делает: отображает результат экспорта (успех/ошибка, путь к файлу, статистику).
    • Ожидает: ExportResult.
  • static void ConfigureCustomFilters(ExportSettings settings)
    • Что делает: запрашивает у пользователя дополнительные паттерны исключения/включения.
    • Ожидает: изменяемый объект ExportSettings.

1.3 InputHelper (статический класс)

Назначение: Безопасное чтение пользовательского ввода с валидацией.

  • static string ReadLine(string message, int maxAttempts = 3, bool allowEmpty = false)
    • Что делает: читает строку, повторяя запрос при пустом вводе (если allowEmpty == false).
    • Ожидает: сообщение, количество попыток, флаг разрешения пустого ввода.
    • Возвращает: введённую строку.
  • static string ReadDirectoryPath(string message, int maxAttempts = 3)
    • Что делает: читает путь и проверяет, что директория существует и доступна.
    • Возвращает: корректный путь.
  • static bool ReadYesNo(string message, bool defaultValue = true)
    • Что делает: читает ответ y/n или использует значение по умолчанию при нажатии Enter.
    • Возвращает: bool.
  • static int ReadChoice(string message, int minValue, int maxValue, int defaultValue)
    • Что делает: читает число в заданном диапазоне.
    • Возвращает: выбранное число.

2. LLMCodeExporter.Core

Назначение: Содержит модели данных (сущности) и интерфейсы (контракты). Этот проект не зависит от внешних слоёв и является ядром бизнес-логики.

Зависимости: Не зависит ни от каких других проектов.

2.1 Модели (пространство имён LLMCodeExporter.Core.Models)

2.1.1 ProjectInfo

Назначение: Хранит информацию о проекте.

Свойства: ProjectPath, ProjectName, List<FileMetadata> Files, List<FileMetadata> ExcludedFiles, ExportMetadata Metadata.

Методы: нет.

2.1.2 FileMetadata

Назначение: Описывает файл.

Свойства: FullPath, RelativePath, SizeInBytes, EstimatedTokens.

2.1.3 ExportMetadata

Назначение: Статистика экспорта.

Свойства: Mode, IncludedFiles, ExcludedFiles, OptimizedSize, EstimatedTokens, OriginalEstimatedTokens, GeneratedAt, AppliedFilters.

Методы: string ToMarkdown() – возвращает Markdown-блок для отчёта.

2.1.4 ExportSettings

Назначение: Настройки экспорта, вводимые пользователем.

Свойства: Mode, ProjectType, Format, FileExtensions, ExcludePatterns, IncludeOnlyPatterns, RemoveComments, RemoveEmptyLines, ConsolidateUsings, MethodCollapseThreshold, OutputDirectory.

Методы (preset'ы): ApplyBackendOnlyPreset(), ApplyDomainServicesPreset(), ApplyCompactAggressivePreset(), ApplyWebAppPreset().

2.1.5 ExportResult

Назначение: Результат экспорта.

Свойства: Success, OutputFilePath, Message, ProjectInfo, Errors.

2.1.6 ProjectType (enum)

AutoDetect, CSharp, Python, JavaScript, TypeScript, WebApp, Generic.

2.1.7 LanguageSettings

Назначение: Настройки для конкретного языка (расширения, папки исключений, точки входа, синтаксис комментариев). Содержит статические фабричные методы: ForCSharp, ForPython, ForJavaScript, ForTypeScript, ForWebApp.

2.2 Интерфейсы (пространство имён LLMCodeExporter.Core.Interfaces)

2.2.1 IProjectAnalyzer

Назначение: Анализ проекта.

  • ProjectInfo AnalyzeProject(string projectPath)
  • ProjectType DetectProjectType(string projectPath)
  • int EstimateFileTokens(string filePath)
  • int EstimateTokens(List<FileMetadata> files)
  • Dictionary<string, object> AnalyzeArchitecture(List<FileMetadata> files, ProjectType projectType)
  • List<string> AnalyzeDependencies(List<FileMetadata> files, ProjectType projectType)

2.2.2 IFileScanner

  • ProjectInfo ScanProject(string projectPath, ExportSettings settings)

2.2.3 ICodeProcessor

  • string ProcessCode(string code, ExportSettings settings)

2.2.4 ICodeOptimizer

  • string Optimize(string content, string filePath, IExportSettings settings)
  • int EstimateTokensAfterOptimization(string content, string filePath, IExportSettings settings)

2.2.5 IOutputFormatter

  • string FormatHeader(ProjectInfo projectInfo)
  • string FormatFile(FileMetadata file, string content, string tag = "")
  • string FormatFooter(ProjectInfo projectInfo)

2.2.6 IExportService

  • ExportResult ExportProject(ProjectInfo projectInfo, ExportSettings settings)

3. LLMCodeExporter.Infrastructure

Назначение: Реализует интерфейсы из Core, содержит конкретную логику работы с файловой системой, оптимизацию кода, форматирование отчётов, а также вспомогательные утилиты.

Зависимости: Ссылается на LLMCodeExporter.Core.

3.1 Реализации интерфейсов

3.1.1 FileScanner (реализует IFileScanner)

  • ProjectInfo ScanProject(string projectPath, ExportSettings settings)
    • Что делает: обходит директории, применяет фильтры FilterBuildFolders, ExcludePatterns, IncludeOnlyPatterns и возвращает ProjectInfo с заполненными списками файлов.
    • Ожидает: путь и настройки.
    • Возвращает: ProjectInfo.
    • Внутренние методы: bool IsExcludedBuildPath(...) – проверяет, лежит ли файл в папках bin, obj и т.п.

3.1.2 UniversalProjectAnalyzer (реализует IProjectAnalyzer)

  • ProjectInfo AnalyzeProject(string projectPath)
    • Что делает: определяет тип проекта, сканирует файлы, анализирует архитектуру и зависимости, заполняет ExportMetadata.
    • Ожидает: путь к проекту.
    • Возвращает: ProjectInfo.
  • ProjectType DetectProjectType(string projectPath)
    • Что делает: по наличию файлов (.csproj, package.json, .py) определяет тип.
    • Возвращает: ProjectType.
  • int EstimateFileTokens(string filePath) – считает file.Length / 4.
  • int EstimateTokens(List<FileMetadata> files) – сумма оценок.
  • Dictionary<string, object> AnalyzeArchitecture(List<FileMetadata> files, ProjectType projectType)
    • Что делает: группирует файлы по папкам и типам, возвращает словарь с информацией о слоях.
  • List<string> AnalyzeDependencies(List<FileMetadata> files, ProjectType projectType)
    • Что делает: анализирует зависимости (например, ищет requirements.txt для Python или PackageReference в .csproj).
  • Внутренние методы: ScanProjectFiles, ShouldExclude, WildcardToRegex.

3.1.3 PythonProjectAnalyzer (наследует UniversalProjectAnalyzer)

  • Переопределяет ScanProjectFiles для учёта requirements.txt и добавляет метод AnalyzePythonDependencies.

3.1.4 CodeProcessor (реализует ICodeProcessor)

  • string ProcessCode(string code, ExportSettings settings)
    • Что делает: если RemoveComments – удаляет комментарии (вызов RemoveComments), если RemoveEmptyLines – удаляет пустые строки.
    • Статические методы: RemoveComments, RemoveEmptyLines.

3.1.5 CodeOptimizer (не реализует интерфейс, используется внутри ExportService)

  • string OptimizeContent(string content, string filePath)
    • Что делает: в зависимости от режима (Compact, Balanced) применяет соответствующую оптимизацию.
    • Для Compact: вызывает ExtractSignatures – оставляет только структуру и сигнатуры методов.
    • Для Balanced: вызывает CollapseLongMethods – сворачивает тела методов, превышающих порог.
  • bool IsAutoGenerated(string filePath) – проверяет .Designer.cs, .g.cs.
  • string GetFileTag(string filePath) – возвращает [auto-generated] или [test].

3.1.6 ExportService (реализует IExportService)

  • ExportResult ExportProject(ProjectInfo projectInfo, ExportSettings settings)
    • Что делает: создаёт CodeOptimizer и нужный IOutputFormatter, для каждого файла читает содержимое → оптимизирует → обрабатывает → форматирует → записывает в выходной файл. Заполняет метаданные и возвращает ExportResult.
    • Внутренние методы: ReadFileContentAsync, GetRecommendedWindow.

3.1.7 MarkdownFormatter (реализует IOutputFormatter)

  • FormatHeader – генерирует заголовок, Quick Links, архитектуру, граф и структуру проекта, используя утилиты NavigationGenerator, ArchitectureAnalyzer, DependencyAnalyzer, ProjectStructureBuilder.
  • FormatFile – оборачивает код в блок ``` с якорем.
  • FormatFooter – итоговая статистика.

3.1.8 PlainTextFormatter (реализует IOutputFormatter)

  • Аналогичен, но генерирует Plain Text.

3.1.9 UniversalCodeOptimizer (реализует ICodeOptimizer)

  • string Optimize(...) – упрощённая оптимизация (удаление лишних пробелов, комментариев, если включена минификация).
  • int EstimateTokensAfterOptimization(...) – оценка токенов после оптимизации.

3.2 Утилиты (пространство имён LLMCodeExporter.Infrastructure.Utils)

Все утилиты – статические классы.

  • Logger – запись логов в Documents/LLMCodeExporter/Logs. Методы: Log, LogError, LogSuccess, LogWarning, GetAppFolderPath, GetCurrentLogFile, CleanOldLogs.
  • PatternMatcher – сопоставление файлов с паттернами (wildcard). Методы: MatchesPattern, MatchesAnyPattern, FilterByPatterns.
  • ProjectStructureBuilder – построение дерева и статистики. Методы: BuildHierarchicalTree, BuildStatisticsByFolder.
  • NavigationGenerator – генерация Quick Links. Метод: GenerateQuickLinks.
  • ArchitectureAnalyzer – определение слоёв. Метод: GenerateArchitectureOverview.
  • DependencyAnalyzer – построение графа зависимостей (Mermaid). Метод: GenerateDependencyGraph.
  • AnchorGenerator – создание якорей для Markdown. Методы: GenerateAnchor, CreateFileLink, CreateFileHeaderAnchor.
  • MethodGrouper – группировка методов по семантике. Методы: GroupMethods, FormatGroupedMethods.
  • ProjectTypeDetector – автоопределение типа. Метод: Detect.

4. Резюме

  • Core – определяет, что нужно делать (интерфейсы) и какие данные (модели).
  • Infrastructure – реализует как это делать (файловая система, оптимизация, форматирование).
  • CLI – связывает всё вместе и управляет пользовательским взаимодействием.
