Логика ключевых методов

На этой странице мы разбираем, как работают основные методы программы: что они делают, какие данные принимают, какие возвращают и какой алгоритм выполняют. Методы сгруппированы по проектам (CLI, Infrastructure). В Core методов нет – только модели и интерфейсы.

1. LLMCodeExporter.CLI

1.1 Program.Main

Сигнатура: static void Main(string[] args)

Назначение: Точка входа. Определяет режим работы (интерактивный или CLI), инициализирует сервисы и запускает экспорт.

Пошаговый алгоритм:

  1. Устанавливает кодировку консоли в UTF-8.
  2. Вызывает ParseArguments(args) для разбора аргументов. Если showHelp == true – вызывает ShowHelp() и завершает работу.
  3. Если hasCliArgs == false (интерактивный режим):
    • Выводит заголовок приложения.
    • Запрашивает путь к проекту через InputHelper.ReadDirectoryPath.
    • Если путь не указан – предлагает использовать текущую директорию.
  4. Нормализует путь через NormalizeProjectPath.
  5. Создаёт экземпляры сервисов: FileScanner, CodeProcessor, ExportService.
  6. В интерактивном режиме:
    • Выполняет предварительное сканирование для получения статистики (с временными настройками).
    • Показывает статистику через InteractiveMenu.ShowProjectStats.
    • Вызывает InteractiveMenu.ConfigureSettings для получения финальных настроек.
    • Повторно сканирует проект с финальными настройками.
  7. В CLI-режиме: использует настройки из аргументов (если они были переданы).
  8. Вызывает ExportService.ExportProject(projectInfo, settings).
  9. Показывает результат через InteractiveMenu.ShowExportResult.
  10. В интерактивном режиме ожидает нажатия клавиши перед выходом.

1.2 Program.ParseArguments

Сигнатура: static (ExportSettings settings, string projectPath, bool showHelp, bool hasCliArgs) ParseArguments(string[] args)

Назначение: Разбирает аргументы командной строки и формирует объект ExportSettings.

Алгоритм:

  1. Инициализирует settings как null, projectPath как null.
  2. Проходит по массиву args:
    • Если аргумент --help, -h или /? – устанавливает флаг showHelp = true.
    • Если аргумент не начинается с -- и projectPath ещё не установлен – сохраняет его как путь (убирая кавычки).
    • Если аргумент начинается с --mode= – устанавливает settings.Mode.
    • Если --format= – устанавливает settings.Format.
    • Если --exclude= – добавляет паттерн в settings.ExcludePatterns.
    • Если --include= – добавляет паттерн в settings.IncludeOnlyPatterns.
    • Обрабатывает preset’ы: --backend-only, --domain-services, --compact-aggressive, --web-app.
    • Обрабатывает флаги: --no-comments, --keep-empty-lines, --no-consolidate-usings.
    • Обрабатывает --collapse-threshold и --output=.
  3. Возвращает кортеж: (settings, projectPath, showHelp, hasCliArgs).

1.3 InteractiveMenu.ConfigureSettings

Сигнатура: static ExportSettings ConfigureSettings(ProjectInfo projectInfo)

Назначение: Проводит интерактивный опрос пользователя и возвращает заполненный ExportSettings.

Алгоритм:

  1. Создаёт новый экземпляр ExportSettings.
  2. Запрашивает тип проекта (1 – C#, 2 – Python, 3 – WebApp) через InputHelper.ReadChoice и устанавливает соответствующие расширения и presets.
  3. Запрашивает режим экспорта (1 – Compact, 2 – Balanced, 3 – Full) и устанавливает settings.Mode.
  4. Запрашивает предустановку фильтров (1 – Без фильтров, 2 – Backend Only, 3 – Domain+Services, 4 – Максимальное сжатие). Применяет соответствующий preset.
  5. Если выбран «Без фильтров», спрашивает, нужно ли добавить кастомные фильтры; если да – вызывает ConfigureCustomFilters.
  6. Запрашивает формат экспорта (Markdown или Plain Text).
  7. Если режим не Full, спрашивает об удалении пустых строк и комментариев (если не выбран агрессивный preset).
  8. Показывает итоговую конфигурацию и спрашивает подтверждение. Если пользователь подтверждает – возвращает settings, иначе – null.

1.4 InputHelper.ReadLine

Сигнатура: static string ReadLine(string message, int maxAttempts = 3, bool allowEmpty = false)

Назначение: Безопасное чтение строки с повторными попытками при пустом вводе.

Алгоритм:

  1. Выводит message в консоль.
  2. В цикле (до maxAttempts) читает строку через Console.ReadLine().
  3. Если строка пустая и allowEmpty == false – выводит предупреждение и повторяет запрос.
  4. Если строка корректна – возвращает её (с обрезанием пробелов).
  5. Если попытки исчерпаны – возвращает null (или пустую строку, если allowEmpty == true).

1.5 Остальные методы InputHelper

Краткое описание:

  • ReadDirectoryPath – аналогичен ReadLine, но дополнительно проверяет существование и доступность папки.
  • ReadYesNo – читает ответ y/n (или Enter для значения по умолчанию), возвращает bool.
  • ReadChoice – читает целое число в заданном диапазоне, возвращает выбранное значение.

2. LLMCodeExporter.Infrastructure

2.1 ExportService.ExportProject

Сигнатура: ExportResult ExportProject(ProjectInfo projectInfo, ExportSettings settings)

Назначение: Основной метод, выполняющий весь процесс экспорта: оптимизация, форматирование, запись.

Пошаговый алгоритм:

  1. Создаёт экземпляр CodeOptimizer.
  2. Создаёт IOutputFormatter (Markdown или PlainText) в зависимости от settings.Format.
  3. Формирует имя выходного файла: code_export_Проект_Режим_дата.расширение.
  4. Открывает поток для записи в выходной файл.
  5. Записывает заголовок через formatter.FormatHeader(projectInfo).
  6. Для каждого файла из projectInfo.Files:
    • Читает содержимое файла через ReadFileContentAsync.
    • Если режим не Full – вызывает codeOptimizer.OptimizeContent(content, file.RelativePath).
    • Вызывает codeProcessor.ProcessCode(optimizedContent, settings).
    • Получает тег файла через codeOptimizer.GetFileTag (например, [test] или [auto-generated]).
    • Записывает отформатированный файл через formatter.FormatFile(file, processedContent, tag).
    • Логирует прогресс через Logger.Log.
  7. Записывает футер через formatter.FormatFooter(projectInfo).
  8. Обновляет метаданные: OptimizedSize, EstimatedTokens, RecommendedContextWindow.
  9. Возвращает ExportResult с флагом успеха, путём к файлу и сообщением.

2.2 CodeOptimizer.OptimizeContent

Сигнатура: string OptimizeContent(string content, string filePath)

Назначение: Применяет оптимизацию в зависимости от режима settings.Mode.

Алгоритм:

  • Если Mode == Full – возвращает исходное содержимое без изменений.
  • Если Mode == Compact:
    • Вызывает ExtractSignatures – разбивает код на строки, находит объявления классов/интерфейсов, извлекает только сигнатуры методов и свойств, группирует их с помощью MethodGrouper и выводит компактно.
    • Если settings.ConsolidateUsings == true – собирает все using в начале.
  • Если Mode == Balanced:
    • Вызывает CollapseLongMethods – анализирует строки, находит методы, считает количество строк в теле. Если метод превышает settings.MethodCollapseThreshold – заменяет тело на // ..., оставляя только сигнатуру и первые 3 строки для контекста.
  • Возвращает полученную строку.
Подметоды:
  • ExtractSignatures – сканирует строки, отслеживает вложенность фигурных скобок, запоминает сигнатуры методов и полей. В конце выводит структуру класса со сгруппированными методами.
  • CollapseLongMethods – аналогично отслеживает начало и конец метода по скобкам; если количество строк в теле больше порога – заменяет тело, иначе оставляет как есть.

2.3 FileScanner.ScanProject

Сигнатура: ProjectInfo ScanProject(string projectPath, ExportSettings settings)

Назначение: Сканирует файловую систему и возвращает ProjectInfo с отфильтрованными файлами.

Алгоритм:

  1. Проверяет существование папки; если нет – выбрасывает исключение.
  2. Создаёт ProjectInfo и заполняет ProjectPath, ProjectName.
  3. Получает все файлы по расширениям из settings.FileExtensions (использует Directory.GetFiles с SearchOption.AllDirectories).
  4. Если settings.FilterBuildFolders == true – фильтрует файлы, лежащие в папках bin, obj, packages (вызов IsExcludedBuildPath).
  5. Применяет паттерны включения/исключения через PatternMatcher.FilterByPatterns.
  6. Для каждого включённого файла создаёт FileMetadata с путями и размером.
  7. Для исключённых файлов также сохраняет метаданные в ExcludedFiles (для статистики).
  8. Заполняет метаданные (TotalFiles, IncludedFiles, AppliedFilters) и возвращает ProjectInfo.

2.4 UniversalProjectAnalyzer.AnalyzeProject

Сигнатура: ProjectInfo AnalyzeProject(string projectPath)

Назначение: Анализирует проект: определяет тип, сканирует файлы, строит архитектуру и зависимости.

Алгоритм:

  1. Создаёт ProjectInfo и заполняет путь и имя.
  2. Вызывает DetectProjectType(projectPath) (или использует явно заданный тип).
  3. Получает LanguageSettings для этого типа.
  4. Сканирует файлы с учётом языка через ScanProjectFiles (переопределяемо в наследниках).
  5. Анализирует зависимости через AnalyzeDependencies (ищет файлы пакетов).
  6. Строит архитектурные слои через AnalyzeArchitecture (группировка по папкам).
  7. Заполняет ExportMetadata: TotalFiles, EstimatedTokens, ArchitectureLayers, Dependencies.
  8. Возвращает ProjectInfo.

2.5 CodeProcessor.ProcessCode

Сигнатура: string ProcessCode(string code, ExportSettings settings)

Алгоритм:

  1. Если settings.RemoveComments – вызывает статический метод RemoveComments, который удаляет однострочные и многострочные комментарии, сохраняя XML-документацию ///.
  2. Если settings.RemoveEmptyLines – вызывает статический метод RemoveEmptyLines, который удаляет избыточные пустые строки, но оставляет одну между логическими блоками (после }).
  3. Возвращает обработанную строку.

2.6 MarkdownFormatter.FormatHeader

Сигнатура: string FormatHeader(ProjectInfo projectInfo)

Назначение: Генерирует заголовок отчёта в Markdown.

Алгоритм: Последовательно добавляет в StringBuilder:

  • Заголовок # Code Export для LLM.
  • Имя проекта и путь.
  • Блок с метаданными (projectInfo.Metadata.ToMarkdown()).
  • Рекомендации по LLM (GetLLMRecommendations()).
  • Quick Links (NavigationGenerator.GenerateQuickLinks).
  • Architecture Overview (ArchitectureAnalyzer.GenerateArchitectureOverview).
  • Граф зависимостей (DependencyAnalyzer.GenerateDependencyGraph).
  • Структуру проекта (ProjectStructureBuilder.BuildHierarchicalTree).
  • Статистику по папкам (ProjectStructureBuilder.BuildStatisticsByFolder).

2.7 Утилитные методы (кратко)

  • PatternMatcher.FilterByPatterns – принимает список файлов и паттерны, возвращает два списка: включённые и исключённые, используя MatchesPattern (с поддержкой wildcard).
  • ProjectStructureBuilder.BuildHierarchicalTree – строит вложенную структуру папок и файлов в виде дерева.
  • ArchitectureAnalyzer.GenerateArchitectureOverview – анализирует пути файлов и классифицирует их по слоям (Domain, Application, Infrastructure, UI, Tests и т.д.) в зависимости от проекта.
  • DependencyAnalyzer.GenerateDependencyGraph – анализирует содержимое файлов (ищет упоминания имён классов) и строит Mermaid-граф.
  • Logger.Log – записывает сообщение в лог-файл с уровнем (Info/Warning/Error/Success), добавляя временную метку.
